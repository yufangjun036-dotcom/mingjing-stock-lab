## 1. 任务理解与核心目标

题目名称：自然语言智能选股与策略解释器。

核心目标：将用户的自然语言研究意图转换为可理解、可修改、可执行的数据条件，以真实金融数据产生研究候选，并让用户核查入选、排除和条件变化的原因。

成功标准不是“AI 给出几只股票”，而是用户能够回答：

1. 系统把我的话理解成了什么条件？哪些是假设？
2. 条件对应什么指标、单位、报告期和计算口径？
3. 哪些股票符合，哪些不符合，哪些因为缺少数据无法判断？
4. 每个判断能否回到原始字段或来源？
5. 修改一个条件后，结果为什么改变？

产品定位：辅助条件筛选和研究核验，不提供直接买卖建议、确定性涨跌预测或收益承诺。

### 1.1 用户与使用场景

- 目标用户：能够描述研究偏好，但不熟悉指标选择和筛选表达式的用户。
- 典型场景：输入“经营改善、估值合理、走势稳定”，确认系统提出的量化解释，修改阈值后执行筛选。
- 第二场景：已知具体条件的用户直接编辑指标及阈值，查看结果和排除原因。
- 第三场景：比较条件 A、B，保存方案以便重新使用。
- 不收集真实持仓、资产、身份证件等个人信息；示例画像采用构造数据。

## 2. 核心流程与功能范围

主流程：输入需求 → AI 生成条件草案和澄清问题 → 用户确认或编辑 → 校验 → 获取并固定数据快照 → 执行筛选 → 展示逐条件证据 → 修改条件并比较 → 保存或导出。

### 2.2 第一版的具体边界

- A 股有限股票池，建议 30–50 只，最终数量取决于数据覆盖；在首页展示实际范围和选择规则。
- 股票池事先确定，不能为了制造漂亮结果而筛完再挑股票；不宣传全市场覆盖。
- 首批约 4–6 个已核验指标；具体字段通过数据可用性测试后锁定。
- 同一组条件采用 AND（全部满足）；不支持的 OR、嵌套逻辑和模糊排名应提示，不擅自改写。
- 无复杂账户系统；方案下载和上传由当前用户操作，不建立所有访客共享的方案列表。
- 不做交易执行、收益预测、新闻研究、行业知识图谱或用户风险评级。
- 不支持的需求必须明确列出；不能静默忽略“稳定”等表达后继续宣称完整理解。

## 3. 是否需要读取其他网站与获取外部数据

### 3.1 结论

需要外部金融数据，也需要阅读官方数据文档，但不需要全网爬虫。模型知识、搜索摘要和网页截图不能替代实际筛选数据。优先通过 API/MCP 获取结构化数据；公司公告或交易所资料用于必要的抽样核验。

三类访问要区分：

1. 阅读文档：了解端点、字段、单位、时间和错误码。
2. 调用接口：取得真正参与筛选的数据。
3. 核验原始来源：对关键数字抽样比对，保留证据定位。

### 3.2 数据来源策略与当前证据

| 来源 | 计划用途 | 当前状态 | 决策 |
| --- | --- | --- | --- |
| 扶摇金融数据 API/MCP | 行情、估值、财务、历史 K 线、交易日历 | 官方快速开始和财务指标文档已读取；尚无本项目金融数据密钥调用成功证据 | 优先验证接入 |
| iFinD MCP | 若权限允许，补充所需金融字段 | 本轮入口读取超时；账户权限与能力未核实 | 不把网页超时解释为账号无权限 |
| 东方财富公开接口 | 备选行情与财务数据 | 前期已收到少量真实 JSON 返回；口径、稳定性及使用/再分发条件未完整核实 | 未通过验证前不列为正式生产来源 |
| 公司公告、交易所页面 | 抽样核验财务数据和披露时间 | 尚未选定样本并完成核对 | 按需阅读，不大规模爬取 |
| OpenAI API | 解析意图、提出待确认条件 | 已完成一次真实最小调用 | 不是金融事实数据源 |

扶摇官方说明要求请求头携带 `X-api-key`；缺失/无效和能力未授权有不同业务错误码。OpenAI 密钥不能用于扶摇。见参考来源 [S1]。

扶摇财务指标文档明确：请求指定股票和报告期；数值可能为字符串或 null；百分比字段按百分数值表达；HTTP 200 仍可能带业务错误码。因此接入必须同时验证 HTTP、业务状态和响应结构。见 [S2]。

### 3.3 数据接入的验收门槛

- 取得合法可用的访问方式，不绕过登录、付费或权限控制。
- 至少验证行情、财务两类所需数据；如提供“走势稳定”，还需验证完整历史价格与复权口径。
- 核实每个字段含义、单位、报告期、披露时点、更新时点及缺失表示。
- 抽样覆盖不同公司和至少一种缺失/异常情况；原值与标准化值对照检查。
- 从部署环境验证接口可达，本机可达不能证明云端可达。
- 确认允许使用的范围；公开可读取不等于允许把全部原始数据上传公开仓库。
- 来源切换必须提示，不能在用户不知情时混用不同估值口径。

优先源不可用时：先说明原因和影响，再验证替代源；若只有获得授权的历史快照，可明确进入“历史快照研究模式”。全无真实可用数据时，不以构造股票数据冒充交付完成。构造数据只能用于标注清楚的自动化测试。

### 3.4 最小证据记录

每条数据或批次应能关联：股票代码及交易所、来源名、无密钥的来源 URL/端点、原始字段名、原始值、标准化值、单位、报告期、披露时间（如可取得）、行情时间、抓取时间、来源更新时间（如可取得）、质量状态、转换公式、快照 ID。

未提供的时间记录为未知，不能用抓取时间填充披露时间。允许保存的原始响应留在受控缓存中；公开仓库仅保留代码、字典及必要的非受限证据摘要。

## 4. 指标定义与量化参考

下列阈值是供用户确认的产品示例，不是金融领域的统一标准或投资建议。字段可用性未验证前，不承诺支持。

| 表达/指标 | 建议量化方式 | 重要边界 |
| --- | --- | --- |
| 经营改善 | 候选解释：营业收入同比 > 0 且归母净利润同比 > 0 | 必须展示并确认；不等同于经营全面改善 |
| 利润增长 | 同口径、同长度报告期间的归母净利润同比变化 | 不把累计三季报与单季度混用；去年负利润/零利润需特殊处理 |
| 估值合理 | 候选解释：0 < 已核验口径的 PE < 用户确认上限 | “低 PE”不等于投资价值；负 PE 不当作便宜；静态/动态/TTM 不混用 |
| 走势稳定 | 候选解释：最近 60 个有效交易日收益率的年化波动率低于确认阈值 | 需要 61 个有效价格点；停牌、缺口、复权不明时不可直接计算 |
| 盈利能力 | 某报告期的 ROE 或毛利率 | 加权/摊薄、年化/非年化需说明；行业可比性有限 |
| 公司规模 | 同一行情时点的总市值，统一换算为亿元 | 总市值与流通市值不混用；不能用静态名称猜测规模 |

若自行计算同比，只在前期值为正且口径可比时使用 `(本期－上年同期)/上年同期×100%`。前期为零或负数时，用明确的“扭亏/亏损收窄/继续亏损”等状态辅助说明；不能用绝对值分母悄悄制造一个标准同比。供应商原始同比可展示，但其负基数口径未经验证时，不参与普通增长筛选。

若实现波动率，拟采用复权价格的简单日收益率 `P_t/P_(t-1)－1`，样本标准差 `ddof=1`，乘 `sqrt(252)×100%` 年化。252 是产品计算约定，不是对实际年度交易日数量的断言；要在字典中说明。若完整行情不足，状态为不可计算。

## 5. 输入、输出和状态规则

### 5.1 输入

- 自然语言：中文研究意图，建议限制 1–500 字。
- 澄清反馈：对指标解释、阈值、范围的选择或补充。
- 条件表单：指标、运算符、有限数值、单位、报告期/窗口。
- 保存方案：带 `schema_version` 的 JSON；只允许白名单字段，建议限制文件 100 KB、条件最多 10 条。
- 外部数据：来自经核验提供方的结构化响应；视为不可信输入并校验。

不接受用户上传任意 Python/SQL 作为筛选条件，不执行模型输出的代码。

### 5.2 输出

- 条件草案：已理解内容、假设、未支持内容、待回答问题。
- 校验结果：可执行状态、冲突位置、修改建议。
- 股票结果：代码、名称、逐条件原值与阈值、通过/失败/未知、汇总状态。
- 数据说明：股票池覆盖、来源、时间、单位、缺失数量及异常信息。
- 比较结果：两组条件差异，进入/退出/保留及未知状态变化；对应同一快照 ID。
- 方案 JSON：版本、条件、股票池标识和时间口径；不含密钥和真实个人数据。
- CSV（P1）：结果和证据摘要；输出文本应防止电子表格公式注入。

### 5.3 决策规则

| 情况 | 处理 |
| --- | --- |
| 所有条件通过 | 入选，展示逐项证据 |
| 至少一个条件失败 | 排除；其余缺失仍须显示 |
| 没有失败，但至少一个条件未知 | 无法判断，不计作入选 |
| 条件为零条 | 提示添加条件，不用空集合逻辑默认选中全部 |
| 条件矛盾 | 不执行；定位矛盾条件 |
| 零只入选 | 正常空结果，说明限制，不自动放宽条件 |
| 接口失败 | 显示数据获取失败；已有结果标为旧结果，不伪装成新结果 |
| 部分股票缺失 | 展示覆盖率和具体缺失，不静默丢掉这些股票 |
| 用户修改未执行 | 标识当前结果来自上一版条件，避免显示关系错乱 |
| 刷新了数据 | 新建快照；旧条件比较仍绑定原快照，或明确发起新的比较 |

条件草案必须由用户确认。AI 解析失败时，可以保留手动条件编辑，但界面要明确“AI 解析失败，当前为手动模式”，不伪造 AI 成功。

## 6. 难点、风险与控制方法

| 难点 | 风险 | 开发处理与验证 |
| --- | --- | --- |
| 自然语言歧义 | AI 捏造用户未说的阈值 | 假设显式化；澄清确认；白名单指标；测试模糊与超范围输入 |
| 财务口径 | 单季度/累计、利润类型和百分比混淆 | 指标字典；同口径转换；抽样核验；不明字段禁用 |
| 时间一致性 | 新旧行情混合、未来披露混入历史判断 | 固定快照；标注报告期与披露时间；不声称支持历史时点回测 |
| 数据异常 | null 变 0、HTTP 200 被误判成功 | 数据结构和业务码双重校验；三态判断 |
| 解释一致性 | AI 编造入选理由 | 原因基于引擎逐条件结果生成；关键数字禁止自由生成 |
| 条件比较 | 数据刷新被误当成阈值影响 | 同快照比较；对照实验只改条件 |
| 模型输出安全 | 提示注入、非法字段、任意代码执行 | 结构校验、输入长度限制、白名单；无 eval/exec |
| 会话隔离 | 不同访客看到彼此方案 | 用户状态独立；仅缓存可共享且允许使用的市场数据 |
| 额度和网络 | 本地能用、上线失败，或公开调用消耗额度 | 提前云端验证；请求长度/并发/频率限制；合理超时和错误提示 |
| 六小时范围 | 花时间做报告而主链路没完成 | P0 优先；文档同步记录；先部署小闭环再迭代 |

## 7. 模糊点逐项澄清与参考答案

以下为开发默认建议，不冒充招聘方补充说明。最终决策应写入技术方案；数据相关答案必须以实测修订。

| 编号 | 模糊点 | 参考答案/默认决策 | 需要何时确认 |
| --- | --- | --- | --- |
| A01 | 必须全 A 股吗？ | 原题未明确；采用透明披露的有限股票池，标明覆盖限制 | 锁定范围时 |
| A02 | 必须实时行情吗？ | 原题未明确；允许标明时点的最新可得数据，不宣传实时 | 数据验证后 |
| A03 | 两个指定源都要用吗？ | 题目写优先使用，不要求同时接入；优先一个满足字段的源 | 接入阶段 |
| A04 | 没有数据权限怎么办？ | 验证授权入口；不可用时评估允许使用的替代源并披露 | 编码主链路前 |
| A05 | 能否用测试假数据展示？ | 测试可用并标注；最终候选必须有真实数据支撑 | 全程 |
| A06 | 经营改善等于什么？ | 提议收入和归母净利同比为正，让用户确认或改单一指标 | 每次相关意图解析 |
| A07 | 估值合理是多少？ | 不设普遍合理值；给出带口径的候选阈值，用户确认 | 每次相关意图解析 |
| A08 | 走势稳定怎么衡量？ | 优先 60 日年化波动率；历史数据不满足时明确不支持 | 数据能力验证后 |
| A09 | 最新财报怎么算？ | 每家公司最新已披露且可核验的报告期，显示各自期间；跨期比较提示 | 字段建模时 |
| A10 | 是否排除 ST、停牌和新股？ | 只有可靠状态字段才可执行；用户可选择已支持排除条件，未知状态需提示 | 股票池定义时 |
| A11 | 多条件用 AND 还是 OR？ | 第一版只支持 AND；遇到 OR 要求调整或提示不支持 | 解析及编辑时 |
| A12 | 阈值边界怎么判？ | 明确支持 >、>=、<、<=、=；内部用未舍入值，显示精度不改变判断 | 引擎实现时 |

| A18 | 解释每只股票的成本太高？ | 有限股票池全部保存逐条件结果，界面分页/搜索；不必每只单独调用模型 | 界面设计时 |
| A19 | 比较的是条件还是市场变化？ | 第一版比较条件影响，固定快照；刷新市场数据单独操作 | 比较模块中 |
| A20 | 保存到哪里？ | 下载 JSON、上传恢复；无用户账号和跨设备云同步承诺 | 第一版固定 |
| A21 | 是否必须回测？ | 选择比较和保存满足延续使用；回测不在本版范围 | 需求基线 |
