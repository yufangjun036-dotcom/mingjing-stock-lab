# 明镜选股：产品与技术设计方案

版本 v0.2｜2026-11-04｜当前实现基线；外网部署尚未验收。

本文描述实际实现及明确待办，不混入早期目标状态。过程修订见 05_AI使用与验证记录；数据依据见 03；测试结果见 04。源码与本文同步维护；每个函数的参数和处理流程见附录 06。

## 1. 产品目标、范围与输入输出

目标用户是希望把选股想法转换为可检查条件的投资研究用户。闭环为“自然语言 → 澄清或条件草案 → 用户编辑和确认 → 真实数据 → 确定性判断 → 证据与条件变化解释”。AI 只负责翻译，不生成金融数据，不决定股票是否入选。

实际范围：固定六只 A 股开发样本，清单见 data/universe.json；固定 2026 年前三季度累计财务；六项指标；1–10 条 AND 条件。不是全市场选股，不支持 OR、行业过滤、实时监控、回测或交易。此前约 30 只股票的设想没有实现，不能作为当前能力宣传。

输入：1–500 字自然语言、可编辑条件表、最大 100 KB 的版本化策略 JSON。条件数值使用 Decimal，绝对值不超过 1e12、有效数字不超过 64 位；不接受 bool、NaN、Infinity、额外字段和未知版本。

输出：条件草案与待澄清事项；所有六只样本的入选/排除/无法判断；每项实际值、阈值、来源和计算输入；同快照前后状态变化；可下载的策略 JSON。JSON 下载保存的是条件，不是原始数据库。

## 2. 方案比较与选型理由

| 决策 | 备选方案 | 优点 | 成本或限制 | 本项目选择 |
| --- | --- | --- | --- | --- |
| 应用结构 | Streamlit 模块化单体 | Python 完成界面和业务，部署与验证链短 | 交互和视觉自由度有限；重跑与会话状态要正确管理 | 采用，适合六小时预算 |
| 应用结构 | FastAPI + 独立前端 | 接口清楚，前端自由度高，可独立扩容 | 需前端代码、两端契约与额外部署工作 | 暂不采用，可后续迁移 |
| 应用结构 | Flask + 模板 | Python 后端，页面可控 | 复杂交互仍需额外脚本和状态处理 | 可作替代，当前收益不足 |
| 数据接入 | 扶摇 REST API | Python 易调用，鉴权及字段已有样本证据 | 需处理业务错误码、限流、口径不一致 | 采用 |
| 数据接入 | 扶摇 MCP | 方便 Agent 使用工具 | 给筛选引擎直接取结构化数据并不必需 | 本版不额外接入 |
| 筛选执行 | 白名单指标 + 确定性表达式 | 可复算、可测试、可逐项解释 | 无法任意执行复杂策略 | 采用，AND 条件 |
| 筛选执行 | AI 生成并运行 Python/SQL | 表达自由 | 无法可靠限制生成代码与口径，验证成本高 | 不采用 |
| 原因生成 | 引擎结果生成中文模板 | 数字、判断、证据一一对应 | 文案变化较少 | 采用，不为每股调用模型 |
| 保存方式 | JSON 下载/上传 + 会话状态 | 无账号系统，跨设备通过文件迁移 | 无云同步 | 采用 |
| 保存方式 | SQLite/云数据库 | 可持久化多用户记录 | 引入身份、权限、迁移和托管存储问题 | 不在首版范围 |
| 部署 | Streamlit Community Cloud | 适配 Python 与 GitHub 源码 | 账号、休眠/资源限制、网络与公开访问需实测 | 优先验证，不视为已部署 |
| 部署 | 通用 Python 容器平台 | 环境可控，可配置更多保护 | 账号、费用和运维增加 | 前者不可用时评估，不擅自采购 |

这些选择是约束下的取舍，不宣称适合所有规模或“绝对最优”。业务逻辑不依赖 Streamlit，以便未来替换页面层。

## 3. UI 与操作状态

页面分为三步：01 描述选股需求，02 检查条件并执行，03 查看结果与证据。侧栏集中展示工作流程和数据口径；主页面始终说明六只样本和固定报告期。导入文件和高级比较操作折叠，主要执行按钮突出显示。条件与方案比较使用中文表格；技术请求元数据仅在证据详情中展示。

当前为 Streamlit 可操作界面，已整理信息层级；不是独立前端，也不声称完成全部设备适配或最终视觉验收。界面组件与筛选算法分开，后续可替换页面而不重写算法。

状态流程：输入 → 解析 → 待澄清/草案 → 编辑 → 勾选确认并点击执行 → 获取快照 → 筛选 → 展示。澄清、未支持意图或拒绝事项存在时阻止执行；用户可明确切换成独立手动方案。导入只恢复草案，不自动联网。

会话实际保存 conditions、editor_revision、draft、blocked、snapshot、result、comparison_base、changes。没有另外实现旧设计中的 draft_revision/confirmed_condition_hash/result_id 状态字段；结果模型自身保存 strategy 和 id，快照保存 id。编辑后的方案与结果中方案不同则提示旧结果；请求失败保留此前结果并提示本次未成功。复选框与显式按钮共同控制执行，不能把一般页面重跑当取数动作。代码热更新后，通过 JSON 将旧模型实例恢复为当前类型。

依赖方向为 app/ui → services → core/data；核心筛选不依赖 Streamlit，不调用模型、不执行生成代码。页面渲染函数不发起金融请求。

## 5. 数据模型、公式与统一规则

Condition 保存 id/metric_id/operator/value；Strategy 保存版本、股票池、报告期、AND 和条件元组。Evidence 保存来源、端点、请求编号、取数时间、供应商时间、原字段原值、单位、参数、报告期、公式及提示，不保存鉴权头。MetricValue 保存数值、质量、原因及证据。StockRecord 保存代码、名称、指标元组。

DatasetSnapshot 保存 SHA256 id、created_at、固定范围、全部股票、source_errors、available_metrics、history_cutoff。ConditionEvaluation 保存条件、实际值及 pass/fail/unknown；StockEvaluation 保存全部逐项判断和总体状态；ScreeningResult 保存 id、strategy、snapshot_id 和 rows。比较输出是状态变化字典列表，没有单独 ComparisonResult 类型。

| 指标 | 实际计算与门槛 |
|---|---|
| PE TTM / PB MRQ | 供应商原值，单位倍；负值不改成零；批次时间超过 7 天标 stale，缺时间标 unverified，超前超过 1 天标 conflict |
| 收入同比 / 归母净利同比 | 同期累计金额 (本期/上年同期−1)×100；前期须为正，零/负基数 not_applicable |
| 毛利率 | (营业收入−营业成本)/营业收入×100；收入须为正；银行成本缺失保持 missing；负毛利率不截断 |
| 60 日年化波动率 | 真实日历最后 61 个前复权正收盘价，60 个简单收益率，样本标准差 ddof=1×√252×100；缺日、重复、非正价不能跳过后继续计算 |

财务核对股票代码、CNY、quarterly、当前及上年 Q3、9 月 30 日期末和重复记录。金额复算与供应商指标交叉检查：同比容差 1e-6 个百分点、毛利率 1e-4 个百分点。缺交叉值为 unverified，重复或不一致为 conflict。茅台公告仅为累计口径抽样核验，不声称所有公司均独立公告审计。

六种质量状态 valid/missing/not_applicable/stale/conflict/unverified 中，仅 valid 参与比较。任一 fail 即排除，但其他 unknown 明细保留；无 fail 而有 unknown 则无法判断；全部 pass 才入选。展示四位小数，比较使用未舍入 Decimal。波动率标准差以 float 计算再转 Decimal，这不等于无限精度计算。

时间使用有时区时间。历史查询保守截止北京时间昨天及以前，即使当天已收盘也不纳入；窗口由真实交易日历确定。估值批次时间不等于逐股成交时间；供应商财务披露字段不能直接当作历史首次披露日，不据此回测。

## 6. 调用、快照与失败处理

扶摇仅开放估值、利润表、财务指标、交易日历、历史价格五个固定端点。固定域名、HTTPS 验证、每请求 15 秒超时、最多两个股票任务并发，不自动重试。HTTP 鉴权/429/服务错误、非法 JSON、业务码不为零、列表结构错误均转安全异常，不回显完整响应。不存在已实现的全流程硬截止或全站调用预算。

估值为所有方案基础；财务条件请求利润表和指标，波动率条件请求日历和价格。每股财务/历史失败保留该股票和缺失原因；估值基础批次失败则本次整体失败，不伪造零候选。没有持久化缓存，当前会话保留不可变快照。

原快照比较不联网且必须覆盖新指标；缺少指标时明确阻断。联合快照比较取两方案指标并集，再在同一新快照执行两套条件，因此不把市场变化误报为阈值影响。快照哈希包含数值、质量、证据和元数据，结果哈希绑定快照与方案。

OpenAI 使用 gpt-4.1-mini 结构化输出，max_retries=0、请求超时 30 秒、最多 1400 输出 token。只发送意图及指标规则。模型输出仍经服务器结构/白名单校验，未解决事项阻断；API 失败不伪造解析结果。错误提示当前合并网络/权限/额度，尚未细分诊断。

## 7. 难点、风险与扩展边界

| 风险或模糊点 | 当前处理 | 剩余边界 |
|---|---|---|
| 经营改善、估值合理、走势稳定 | 请求用户明确指标与阈值；不自行替用户确定 | 澄清是重新输入，不是多轮结构化表单 |
| 低估值负 PE | 正值前提作为假设展示并由用户确认 | 不独立重建估值分母 |
| 财务累计/单季混用 | 固定累计 Q3，报表检查、复算和抽样公告验证 | 未逐公司原始公告审计 |
| 缺失误当不满足 | 三态结果和原字段证据 | 供应商本身可能有错误 |
| 新旧数据混用 | 冻结快照，联合重算基准与新方案 | 不支持历史时点回放 |
| 多用户成本与公开访问 | 每点击显式触发、并发 2、有限超时 | 无全站配额/身份系统；大规模公开使用前须增加预算和访问保护 |
| 密钥/配置 | 环境优先；本地文件忽略；异常去敏；验证 HTTPS | 云端 Secrets 尚待配置与核验 |
| 扩展指标与股票池 | 先补数据证据、字典、标准化和测试，再开放 UI | 不允许只加模型提示就宣称支持 |
| 页面状态和热更新 | 结果绑定方案，变更提示，实例 JSON 恢复 | 未做浏览器关闭后的持久化 |

### 9.2 核心测试样例及断言

下列为测试策略清单，不意味着每条均已完成实测；执行证据以 04 为准。

- PE=10：`>10` 不通过，`>=10` 通过；显示为 10.00 不改变原始值比较。
- `PE>30 AND PE<10` 冲突；`PE>=10 AND PE<=10` 可执行。
- 一个 fail、一个 unknown：股票排除，但未知详情保留；全部 pass 才入选。
- 零条条件拒绝；合法条件无候选是正常结果；两者不可混淆。
- 归母净利前期 -100、本期 -80：不得产生普通“盈利增长20%”入选结论；可说明亏损收窄。
- 银行营业成本 null：毛利率未知，不填零；负毛利率原值可存在。
- 恒定正价格序列：波动率为 0；61 点产生 60 个收益率；缺交易日不能简单删掉后继续凑够 61 点。
- 同样数据和条件判断相同；修改非相关阈值不应改变其他逐条件事实。
- 放宽一个 AND 下界，在同快照且相同有效性策略下，原已入选集合不应缩小；作为性质测试。
- 比较快照不一致时拒绝；新增指标无历史快照数据时重新取得联合数据并重算两方案。
- 结构化 JSON 中含不存在指标、超长内容、NaN、额外可执行代码时拒绝。
- 扶摇 HTTP 200 + code=1002/3001 不当成功；code=0 + 空列表与连接失败分别处理。
- 上传 JSON 只恢复草案；不自动联网或运行；恶意 HTML 在页面按文本显示。
- 模型失败后手动筛选可用，但页面标识降级，AI 验收仍记失败。
