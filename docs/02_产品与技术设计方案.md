## 1. 设计结论与范围

采用 Python 模块化单体应用：Streamlit 页面、Pydantic 数据契约、Pandas 表格处理、HTTPX 数据请求、OpenAI 结构化意图解析、确定性筛选与解释、pytest 测试。产品代码不依赖 JavaScript Worker。已有 Worker 模板是早期初始化产物，切换时清理不再使用的模板文件，保留密钥及文档；已注册的 Sites 站点未发布，不作为最终 Python 部署成果。

数据主源确定为扶摇官方 API，暂不接东方财富或 iFinD。当前扶摇六类接口已在样本上验证可访问，因此没有必要为凑数据源数量增加接口。iFinD 保留为后续必要能力的候选，不宣称已接入。

首版围绕六项指标设计：PE TTM、PB MRQ、营业收入同比、归母净利润同比、销售毛利率、60 日年化波动率。指标能否启用由下文质量门槛决定，不因出现在方案中就默认已核验。

股票池按固定、可见的代码清单组织，候选目标约 30 只。应在批量获取前锁定清单和选择原则，不根据筛选结果倒选股票；具体清单在代码表及覆盖核验后生成。不能把 6 只核验样本说成全量股票池。

## 2. 方案比较与选型理由

| 决策 | 备选方案 | 优点 | 成本或限制 | 本项目选择 |
| --- | --- | --- | --- | --- |
| 应用结构 | Streamlit 模块化单体 | Python 完成界面和业务，部署与验证链短 | 交互和视觉自由度有限；重跑与会话状态要正确管理 | 采用，适合六小时预算 |
| 应用结构 | FastAPI + 独立前端 | 接口清楚，前端自由度高，可独立扩容 | 需前端代码、两端契约与额外部署工作 | 暂不采用，可后续迁移 |
| 应用结构 | Flask + 模板 | Python 后端，页面可控 | 复杂交互仍需额外脚本和状态处理 | 可作替代，当前收益不足 |
| 数据接入 | 扶摇 REST API | Python 易调用，鉴权及字段已有样本证据 | 需处理业务错误码、限流、口径不一致 | 采用 |
| 数据接入 | 扶摇 MCP | 方便 Agent 使用工具 | 给筛选引擎直接取结构化数据并不必需 | 本版不额外接入 |
| 筛选执行 | 白名单指标 + 确定性表达式 | 可复算、可测试、可逐项解释 | 无法任意执行复杂策略 | 采用，AND 条件 |
| 筛选执行 | AI 生成并运行 Python/SQL | 表达自由 | 无法可靠限制生成代码与口径，验证成本高 | 不采用 |
| 原因生成 | 引擎结果生成中文模板 | 数字、判断、证据一一对应 | 文案变化较少 | 采用，不为每股调用模型 |
| 保存方式 | JSON 下载/上传 + 会话状态 | 无账号系统，跨设备通过文件迁移 | 无云同步 | 采用 |
| 保存方式 | SQLite/云数据库 | 可持久化多用户记录 | 引入身份、权限、迁移和托管存储问题 | 不在首版范围 |
| 部署 | Streamlit Community Cloud | 适配 Python 与 GitHub 源码 | 账号、休眠/资源限制、网络与公开访问需实测 | 优先验证，不视为已部署 |
| 部署 | 通用 Python 容器平台 | 环境可控，可配置更多保护 | 账号、费用和运维增加 | 前者不可用时评估，不擅自采购 |

这些选择是约束下的取舍，不宣称适合所有规模或“绝对最优”。业务逻辑不依赖 Streamlit，以便未来替换页面层。

## 3. 产品页面与用户流程

### 3.1 页面板块

1. **意图与条件**：输入框、示例需求、解析按钮、假设/未支持事项、澄清选项、可编辑条件表、确认执行按钮。
2. **结果与证据**：股票池规模、数据时点、入选/排除/无法判断计数；股票结果表；逐条件实际值、阈值、原字段、来源、计算式与质量提示。
3. **方案比较**：选择同一快照上的基准方案、编辑条件并重算；显示进入、退出、保留和状态转换。
4. **数据与方法**：实际可用指标、固定报告期、数据刷新状态、单位、公式、已知限制；下载/载入方案入口。

没有候选时明确显示“0 只符合当前条件”。接口失败时显示错误与重试入口，不把空表格伪装成正常零结果。不提供买入按钮、目标价或收益预测。

### 3.2 状态流转

```text
未输入 → 解析中 → 条件草案/待澄清 → 用户确认 → 条件校验
                                       ↓ 校验成功
                                获取所需数据 → 固定快照
                                       ↓
                                确定性筛选 → 结果
                                       ↓
                         修改条件 → 草案已变更 → 确认重算

任一调用失败 → 显式错误状态；已有结果保留但标为旧结果
刷新数据 → 创建新快照；不覆盖正在用于条件比较的原快照
```

状态分开存储：`draft_revision`、`confirmed_condition_hash`、`snapshot_id`、`result_id`。编辑时递增草案版本，旧结果仍绑定原条件；只有用户点击确认执行才产生新结果。模型调用、取数都不得在普通页面重跑时重复触发。

## 4. 数据契约与职责边界

### 4.1 核心数据模型

| 模型 | 核心字段 | 约束 |
| --- | --- | --- |
| MetricDefinition | id、中文名、unit、period_kind、supported_ops、formula、required_sources、activation_status | 由服务器维护；模型不能添加指标 |
| Condition | id、metric_id、operator、value | Decimal 有限值；指标和操作符白名单；单位与周期从字典取得 |
| Strategy | schema_version、universe_id、report_period、logic、conditions | logic 仅 AND；1–10 个条件；版本受支持 |
| IntentDraft | conditions、assumptions、clarifications、unsupported、refusal_reason | 有未解决澄清或拒绝原因时不可直接执行 |
| Evidence | source、endpoint、params、request_id、retrieved_at、source_time、raw_field、raw_value、unit、report_period、report_date、formula | 参数去密钥；未知时间为 null；计算指标关联全部输入 |
| MetricValue | value、quality、reason、evidence | valid/missing/not_applicable/stale/conflict/unverified；只有 valid 可参与比较 |
| StockRecord | thscode、name、metrics | 股票清单驱动，接口漏返回时仍保留该股票 |
| DatasetSnapshot | id、created_at、universe_id、report_period、records、source_errors、quality_summary | 创建后不可变；包括质量状态和元数据 |
| ConditionEvaluation | condition_id、actual、operator、threshold、status、reason、evidence | pass/fail/unknown，不由模型填写 |
| ScreeningResult | id、strategy、condition_hash、snapshot_id、rows、counts、created_at | 完整保存当时条件，不指向可变草案 |
| ComparisonResult | baseline_result_id、new_result_id、entered、exited、retained、status_changes | 股票池、报告期和快照 ID 必须相同 |
| ProviderError | category、safe_message、retryable、request_id | 不包含请求头、密钥、完整异常对象 |

数值解析优先 Decimal，禁止把 null、空字符串、NaN、Infinity 转成可筛选数值。展示可四舍五入，但阈值比较使用未舍入值。JSON 导出阈值使用十进制字符串，导入时明确解析；界面显示单位，避免 20% 与 0.2 的混淆。

### 4.2 示例契约（格式示例，非真实筛选结果）

```json
{
  "schema_version": "1.0",
  "universe_id": "a_share_demo_v1",
  "report_period": "2026-3",
  "logic": "AND",
  "conditions": [
    {"id": "c1", "metric_id": "pe_ttm", "operator": ">", "value": "0"},
    {"id": "c2", "metric_id": "pe_ttm", "operator": "<", "value": "25"}
  ]
}
```

示例阈值仅用于表达格式，不代表推荐值。模型提出的阈值必须展示为待确认假设。

### 4.3 指标启用与计算

| 指标 | 数据依赖 | 算法与门槛 |
| --- | --- | --- |
| pe_ttm | 估值快照 | 原值映射，倍；负值可显示但不符合“低估值”的默认正值前提；不替换成 pe_mrq |
| pb_mrq | 估值快照 | 原值映射，倍；非正值单独说明，不当作常规便宜 |
| revenue_yoy | 当期和上年同期间利润表 | 前期收入 > 0，口径确认后 `(当前/前期-1)×100`；累计/单季未确认时 quality=unverified |
| profit_yoy | 同期归母净利润 | 前期 > 0 才计算普通同比；前期 <= 0 标 not_applicable，另展示扭亏/亏损变化说明 |
| gross_margin | 同期营业收入和营业成本 | 收入 > 0 且成本有效；`(收入-成本)/收入×100`；不适用行业/null 保留未知；不擅自截断负毛利率 |
| volatility_60d | 前复权日线 + 交易日历 | 取最后 61 个连续有效交易日价格，计算 60 个简单收益率，样本标准差×sqrt(252)×100；不足、缺口、非正价格时未知 |

产品首次启动前必须核实财务累计口径，并记录依据。如果未完成，仍可开发测试公式，但上线时对应财务指标应禁用或返回未核实；不得把核心功能缺失写成已通过。营业改善类主链路未能启用时，整体验收应明确未完成。

所有金额按接口原币元保留；显示亿元时除以 1e8，并标明显示单位；EPS 是元/股不能按金额缩放。百分比字段的 2.4 表示 2.4%，不能再乘 100。

### 4.4 时间策略

- 前端展示使用 Asia/Shanghai；内部使用带时区时间或明确的 Unix 毫秒。
- 报告期采用明确的 `2026-3`（本轮设计基线），页面可见；不冒充逐公司自动发现最新财报。
- 财务 `period_end_ms` 是报告期末，`report_date_ms` 是供应商披露字段。旧期日期异常时标记语义未核实，不用于历史可得性回测。
- 行情与估值 `timestamp` 是批次上游元数据时间，不是每股成交时间。时效状态应区分“批次更新时间可见”和“逐股时间未知”。
- 波动率截至最后已完成交易日。市场尚未收盘时不把当天不完整 K 线并入 60 日窗口。
- 交易日历不可用时，禁止计算“连续 60 交易日”的指标；不靠周一至周五猜测节假日。
- 在固定数据快照上修改条件，可继续比较，但明确显示快照时间。数据刷新是独立操作，创建新 ID。

## 5. 分模块与函数详细设计

本节列出的函数为实施合同，尚未全部实现。每个函数都应有中文 docstring，说明用途、参数、返回值、异常和关键口径；具体实现调整时同步修改本文。

### 5.1 配置与数据模型

| 文件/函数 | 输入 → 输出 | 具体流程 | 异常与测试 |
| --- | --- | --- | --- |
| config.py / load_settings() | 环境和私密配置 → Settings | 先读取部署环境变量；本地补充 .env.local/.env.fuyao；校验必要配置；只返回配置对象，不打印值 | 缺项返回安全错误；验证环境优先级及无敏感日志 |
| config.py / build_ssl_context(settings) | CA 设置 → SSLContext | 优先显式可信 CA；否则可用 certifi/系统信任库；保留验证与主机名校验 | 无有效 CA 时报错，不关闭验证；本地/部署分别测试 |
| core/schemas.py / 模型 validators | 原始数据 → 类型化模型 | 检查必填项、版本、枚举、长度、有限数字；禁止额外字段 | 未知字段、NaN、布尔值当数字、超长文本均拒绝 |
| core/metrics.py / get_metric(id) | 指标 ID → MetricDefinition | 只查固定注册表；返回单位、依赖、启用状态 | 未知 ID 拒绝；不能动态执行公式字符串 |
| core/metrics.py / list_enabled_metrics() | 当前能力 → 指标清单 | 按核验标记过滤；为 UI 和模型提供同一份白名单 | 未启用字段不能被模型绕过 |

### 5.2 数据提供方：data/provider.py

定义 FuyaoClient；只允许固定域名及方法封装，不接受用户提供任意 URL。对请求参数长度和格式做校验。

| 函数 | 输入 → 输出 | 具体流程 | 异常与测试 |
| --- | --- | --- | --- |
| request_json(path, params) | 固定端点及参数 → ResponseEnvelope | 加入鉴权头；发起 HTTPS；检查 HTTP/JSON/业务码/结构；生成去敏诊断 | 认证错误不重试；超时/服务不可用最多一次延迟重试；429 尊重 Retry-After，超出等待预算就提示稍后重试 |
| get_valuations(codes) | 已验证代码列表 → 批次及证据 | 去重保持顺序；每批不超过官方上限 100；核对返回代码；映射 pe_ttm/pb_mrq | 漏返回标记缺失；非法代码单独记录；测试负 PE 和 null |
| get_quotes(codes) | 代码列表 → 行情批次 | 按代码请求；记录批次时间；保留原单位 | 没有名称时不凭空填写；用可靠代码表/估值名称 |
| get_income(code, limit=8) | 单股票 → 利润表记录 | 使用 quarterly 最近 8 期；校验日期与币种；按报告期索引 | 不把每个季度末理解为单季度金额；检查重复及异样披露日期 |
| get_indicators(code, report) | 股票/报告期 → 指标映射 | 遍历分组；按明确别名映射；保留 null 和原字符串 | 未知字段忽略其计算用途并记诊断；重复冲突值返回 conflict |
| get_calendar(start, end) | 日期闭区间 → 交易日序列 | 校验日期；解析并检查 date 与 date_ms 一致；排序去重 | 反向范围、本地日历猜测禁止；空区间与失败区分 |
| get_history(code, start, end) | 单股票/区间 → 前复权日线 | 固定 1d/forward；记录参数；验证日期、价格及排序 | 重复日期冲突、缺口、非正收盘价保留质量问题 |

默认设计：请求超时 15 秒，总重试最多 1 次，并发不超过 2；这些是应用配置，不是供应商服务承诺。真实 429 时降低负载，不通过密集重试绕过限流。整次流程设置总时间预算，保留已完成项并显式报告未完成项，不无限卡住。

### 5.3 标准化与计算：data/normalizer.py

| 函数 | 输入 → 输出 | 具体流程 | 异常与测试 |
| --- | --- | --- | --- |
| parse_decimal(raw) | 原值 → Decimal 或缺失 | null/空标识转缺失；拒绝 bool；解析有限十进制；保留原值证据 | 非法字符串、无限值返回质量错误 |
| select_report_pair(rows, report) | 报表序列/期间 → 当前与上年同期 | 按年份和财政季度准确匹配；检查币种、字段和期间；检查披露异常 | 缺任一期则未知；禁止用相邻季度代替去年同期 |
| compute_yoy(current, prior, evidence) | 同口径金额 → MetricValue | 先验证口径和基数；正基数计算同比；绑定两个输入字段 | 负/零基数不产生普通增长百分比；测试扭亏和持续亏损 |
| compute_gross_margin(row) | 报表行 → MetricValue | 验证收入为正及成本有效；按公式计算；附原值 | 银行 null 不填零；毛利率负数不自动报错或截断 |
| compute_volatility(bars, calendar, cutoff) | 日线/日历/截止日 → MetricValue | 对齐最后 61 个交易日；检查正价与连续性；计算 60 个收益率、ddof=1、年化 | 缺一天、停牌缺口、重复冲突、不足 61 点均未知 |
| normalize_stock(code, source_results) | 多源响应 → StockRecord | 按股票池代码合并；生成六项值和证据；保留各字段质量 | 不因接口漏返回而丢失股票；不同指标独立质量状态 |
| build_snapshot(records, metadata) | 标准化记录 → DatasetSnapshot | 规范排序序列化；内容与元数据生成 SHA-256 ID；冻结数据 | 同快照不被后续 UI 编辑修改；序列化确定性测试 |

同源财务指标用于金额计算交叉核对；差异超过精度容差时记 conflict，不自动选取更有利的结果。初始容差参考样本显示精度（同比 1e-6 个百分点、毛利率 1e-4 个百分点），上线前按字段精度固定，不把容差当经济意义上的误差许可。

### 5.4 意图解析：core/intent_parser.py

| 函数 | 输入 → 输出 | 具体流程 | 异常与测试 |
| --- | --- | --- | --- |
| build_intent_prompt(text, metrics, feedback) | 文本/白名单/澄清 → 请求内容 | 注入可用字段、单位、固定范围、AND 规则；要求列出假设与未支持意图；禁止荐股和数字捏造 | 用户文字视为数据；不把其中“忽略规则”等当系统指令 |
| parse_intent(text, feedback) | 1–500 字 → IntentDraft | 调用配置模型，默认采用已验证可访问的 gpt-4.1-mini；请求结构化响应；识别拒绝/不完整输出 | 网络、额度、模型拒绝分别说明；不悄悄改用模拟结果 |
| validate_intent_draft(raw, registry) | 模型 JSON → 合法草案 | Pydantic 校验；再次校验字段/操作符/范围；保留 unsupported 和澄清 | 未知字段、超过 10 条、未解决 OR 需求不得执行 |

一次用户点击对应一次解析调用；不在表单每次重跑时调用。发送给模型的是用户意图、白名单和必要澄清，不发送 API Key、个人持仓或整份原始金融数据库。不保存模型内部推理链，只记录任务提示、结构化结果和可公开的纠错证据。

### 5.5 条件校验：core/condition_validator.py

| 函数 | 输入 → 输出 | 具体流程 | 异常与测试 |
| --- | --- | --- | --- |

“数据上无人满足”不是逻辑冲突，校验器不通过历史样本猜测冲突。不同指标的经济关系不做未经证明的自动矛盾判定。

## 6. 缓存、费用、隔离与安全边界

- 首版优先会话内缓存，不用共享可变对象保存用户条件；避免扩大许可数据的可见范围。
- 缓存键至少含提供方、股票代码、报告期/区间、复权方式、字段版本；换凭据或配置时清空相关缓存，不把原密钥写入缓存键或日志。
- 建议行情/估值刷新缓存 5 分钟、财务 1 小时；这是刷新策略，不是数据新鲜度保证。历史分析快照持续显示原取数时间。
- 失败不写入成功缓存；旧数据只能明确标注为旧快照继续查看，刷新失败不能改成新时间。
- 原始响应不写入公开 Git 仓库。测试 fixtures 为构造数据，文件头标明用途；真实源抽样记录保留请求 ID、时间和必要字段。
- 浏览器只接触结果和用户输入；API Key 始终在 Python 服务端。环境文件进入 .gitignore，日志和异常消息脱敏。
- 意图长度、条件数、文件大小、股票池数量、请求并发均限制；同会话限制重复模型调用。会话限流不是全站硬预算，发布前还应核实提供方用量/额度控制；不能承诺公开访问不会产生额外调用。
- 数据是否允许公开展示/导出按实际授权和条款核实；若限制公开访问，选择招聘方可访问的授权部署方式。不能只部署本人可见页面却宣称招聘方可用。

### 9.2 核心测试样例及断言

- PE=10：`>10` 不通过，`>=10` 通过；显示为 10.00 不改变原始值比较。
- `PE>30 AND PE<10` 冲突；`PE>=10 AND PE<=10` 可执行。
- 一个 fail、一个 unknown：股票排除，但未知详情保留；全部 pass 才入选。
- 零条条件拒绝；合法条件无候选是正常结果；两者不可混淆。
- 归母净利前期 -100、本期 -80：不得产生普通“盈利增长20%”入选结论；可说明亏损收窄。
- 银行营业成本 null：毛利率未知，不填零；负毛利率原值可存在。
- 恒定正价格序列：波动率为 0；61 点产生 60 个收益率；缺交易日不能简单删掉后继续凑够 61 点。
- 同样数据和条件判断相同；修改非相关阈值不应改变其他逐条件事实。
- 放宽一个 AND 下界，在同快照且相同有效性策略下，原已入选集合不应缩小；作为性质测试。
- 比较快照不一致时拒绝；新增指标无历史快照数据时重新取得联合数据并重算两方案。
- 结构化 JSON 中含不存在指标、超长内容、NaN、额外可执行代码时拒绝。
- 扶摇 HTTP 200 + code=1002/3001 不当成功；code=0 + 空列表与连接失败分别处理。
- 上传 JSON 只恢复草案；不自动联网或运行；恶意 HTML 在页面按文本显示。
- 模型失败后手动筛选可用，但页面标识降级，AI 验收仍记失败。
