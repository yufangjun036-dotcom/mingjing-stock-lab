# 查询性能优化与实测（2026-11-04）

## 修改范围
五分钟进程内快照缓存最多8份，按凭据摘要、股票池、报告期、指标集合和北京时间日期隔离。阈值变化不需要新数据；有效缓存命中不创建客户端或消费外部额度。同范围同时冷查询通过锁合并取数，但两个冷请求各自保留操作额度和并发槽。缓存保留原采集时间，过期后重新查询；接口失败快照不缓存，不用过期数据掩盖错误。缓存不跨进程、不跨重启。

详细证据原先即使折叠也会生成多个表格；现在显式勾选后才构建解释及原始证据。不能因此断言原先用户卡顿唯一原因就是证据渲染。45秒页面等待保护保留，后台清理完成前占用并发槽，取消后不继续请求新端点。

模块：services/snapshot_cache.py维护TTL与合并锁；screening_service.py管理缓存与计算；external_operation.py在联网前检查缓存；results_panel.py按需加载证据。benchmark_screening.py提供可重复的真实供应商服务层测量脚本。

## 软件与真实接口验证
73项回归通过（3.51秒），包括TTL、凭据隔离、阈值变化复用、指标缺失不命中、失败不缓存、两个冷查询只取一次、暖查询不消耗接口额度。证据：剩余验收证据/performance_regression.xml。

真实接口小样本：八条复杂条件首次冷取数0.9625秒（20次请求）；暖查询三次0.0091、0.0062、0.0060秒（0次请求）；同快照计算三次0.0002、0.0001、0.0001秒；两个会话同时冷查询分别1.0850和1.0845秒，总共20次请求。各轮六股全部排除，无源接口错误。本次合计40个HTTP请求、3个受保护外部操作。原始测量汇总：剩余验收证据/real_performance.json。样本太少，不宣称P95达标、持续负载能力或浏览器端到端延迟。

## 浏览器复验与实际遇到的失败
Chrome首次刷新发现旧服务未加载cached_screening，出现ImportError；随后停止原服务器会话并完整重启8511本地服务。重启后页面显示新版标题、默认收起的新手入口及正常表单。实际点击默认PE>0且<25查询，显示5入选、1排除、0未知，快照c85f0f8321b9，采集时间2026-11-04T06:00:03.838899+08:00；再次点击后相同快照与时间保持不变，无页面错误。浏览器此次验证的是估值流程，复杂八条件的上述计时来自服务层，不能混同。
